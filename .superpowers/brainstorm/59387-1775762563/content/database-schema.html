Key Design Decisions

Dual Market (US + India)

  • country field on all price tables (IN/US)
  • currency field (INR/USD) — no conversion needed
  • City-level granularity for both markets
  • Separate pricing_knowledge rows per country
  • User's country detected from profile, overridable per query

pgvector for Similarity

  • Embeddings on community_prices and pricing_knowledge
  • "Brake pad replacement Honda City 2020 Mumbai" → find similar past queries
  • Cosine similarity search for relevant price data
  • Supabase has pgvector built-in on free tier

JSONB for Flexibility

  • red_flags, questions_to_ask, sources_used as JSONB
  • Different domains produce different structured outputs
  • Auto: parts list, labor breakdown, OEM vs aftermarket
  • Medical: drug names, generic alternatives, dosages
  • No need for rigid schemas on domain-specific data

Row-Level Security (RLS)

  • Users can only read their own queries & reviews
  • Community prices are read-public, write-authenticated
  • Pricing knowledge is read-public (the core product value)
  • Vendor data is read-public, write-admin-only
  • Supabase Auth handles JWT → RLS automatically

Critical Indexes

  • pricing_knowledge(domain, country, city, category) — fast lookup by domain + location
  • community_prices(domain, city, country, created_at DESC) — recent local prices
  • queries(user_id, created_at DESC) — user history
  • pricing_knowledge USING ivfflat (embedding vector_cosine_ops) — vector similarity
  • community_prices USING ivfflat (embedding vector_cosine_ops) — community similarity
  • vendors(domain, city, country, is_verified) — verified vendor lookup
